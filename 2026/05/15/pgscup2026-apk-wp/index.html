PGSCUP 2026 | 方俊朗 phone.E01 检材 — APK 分析 WriteUp

2026/5/15 WriteUp PGSCUP APK取证 Android逆向 壳分析 SQLCipher

比赛背景： 2023 年 8 月，境外「龙腾四海」犯罪集团在我国设立「金鳞资本」投资诈骗窝点，利用物联网入侵、AI 技术及 Deepfake 深度伪造等手段实施精准诈骗。

本文为 PGSCUP 2026 手机取证赛道 —— 方俊朗 phone.E01 检材的 APK 分析部分解题记录。

Q1：壳代码解密密钥还原

题目： 分析应用的壳代码逻辑，解密密钥由 3 个字符串片段混淆拼接而成。还原完整密钥明文。

分析过程

Step 1 — 定位加壳应用

从 E01 镜像 data 分区 /app/ 目录中提取 APK，使用 androguard 批量检测：

APK 包名 DEX 数 特征
socialchat.apk com.socialchat.social_chat_app 1 Flutter + SQLCipher
flysilkworm.apk com.android.flysilkworm 5 大型商业应用
predictor.apk com.example.predictor 3 壳加载器

Step 2 — 识别壳特征

predictor.apk 的 AndroidManifest.xml 中：

<application android:name="com.shell.loader.ShellApplication" ...>

存在 assets/original_res/libsqlcipher.so（原始资源被壳隐藏），DEX 倒序排列（classes3.dex → classes.dex）。

Step 3 — 静态分析 ShellApplication.smali

APKTool 解码后在 smali_classes3/com/shell/loader/ShellApplication.smali 中发现关键方法：

buildDecryptionKey() — 三段密钥拼装：

.method private buildDecryptionKey()Ljava/lang/String;
    invoke-direct {p0}, Lcom/shell/loader/ShellApplication;->getKeyPart1()Ljava/lang/String;
    move-result-object v1
    invoke-virtual {v0, v1}, Ljava/lang/StringBuilder;->append(Ljava/lang/String;)Ljava/lang/StringBuilder;
    
    invoke-direct {p0}, Lcom/shell/loader/ShellApplication;->getKeyPart2()Ljava/lang/String;
    move-result-object v1
    invoke-virtual {v0, v1}, Ljava/lang/StringBuilder;->append(Ljava/lang/String;)Ljava/lang/StringBuilder;
    
    invoke-direct {p0}, Lcom/shell/loader/ShellApplication;->getKeyPart3()Ljava/lang/String;
    move-result-object v1
    invoke-virtual {v0, v1}, Ljava/lang/StringBuilder;->append(Ljava/lang/String;)Ljava/lang/StringBuilder;

getKeyPart1() — Base64 解码：

const-string v0, "U2gzbGxf"
invoke-static {v0, v2}, Landroid/util/Base64;->decode(Ljava/lang/String;I)[B

base64_decode("U2gzbGxf") = Sh3ll_

getKeyPart2() — XOR 0x11 混淆：

fill-array-data v0, :array_0        # [0x5d, 0x21, 0x70, 0x75, 0x22, 0x63, 0x4e, 0x5a]
:loop
    aget-byte v2, v0, v1
    xor-int/lit8 v2, v2, 0x11
原始 XOR 0x11 字符
0x5d 0x4c L
0x21 0x30 0
0x70 0x61 a
0x75 0x64 d
0x22 0x33 3
0x63 0x72 r
0x4e 0x5f _
0x5a 0x4b K

→ L0ad3r_K

getKeyPart3() — 字符串反转：

const-string v0, "!4202_y3"
invoke-virtual {v1}, Ljava/lang/StringBuilder;->reverse()...

reverse("!4202_y3") = 3y_2024!

✅ 答案

Sh3ll_L0ad3r_K3y_2024!

载荷解密验证

用还原的密钥成功解密 payload.dat（10MB），获得 3 个隐藏 DEX：

DEX #0: classes3.dex (25KB)  — ChatDatabaseHelper, KeyDeriver, HistoryActivity
DEX #1: classes2.dex (605KB) — 资源类
DEX #2: classes.dex  (9.8MB) — 完整应用代码

Q2：反调试自杀调用的 Java 系统方法签名

题目： 当选手尝试使用 frida-dexdump 等通用脱壳工具动态附加时，应用会立刻闪退。写出触发进程自杀的完整 Java 系统方法签名。

分析过程

在 ShellApplication.smali 中，startAntiDumperDaemon() 启动后台守护线程，循环执行两层检测：

检测层 1 — TracerPid（调试器检测）

const-string v3, "TracerPid:"
invoke-virtual {v4, v3}, Ljava/lang/String;->startsWith(Ljava/lang/String;)Z
# ... 解析 TracerPid ...
if-eqz v3, :cond_1           # TracerPid != 0 → 进入自杀
const-string v5, "FATAL: Tracer detected! Self-destructing!"
invoke-static {v0, v5}, Landroid/util/Log;->e(...)
invoke-static {v1}, Ljava/lang/System;->exit(I)V   # ← Line 635

检测层 2 — Frida 内存模块检测

const-string v3, "frida-agent"
invoke-virtual {v4, v3}, Ljava/lang/String;->contains(Ljava/lang/CharSequence;)Z
# ... 同样检查 "frida-gadget" ...
const-string v3, "FATAL: Frida memory module detected! Self-destructing!"
invoke-static {v1}, Ljava/lang/System;->exit(I)V   # ← Line 715

两处均调用 Ljava/lang/System;->exit(I)V，参数 v1 = 0。

✅ 答案

java.lang.System.exit

壳加载器完整流程

attachBaseContext()
  ├─ exemptAllHiddenApi()       → 绕过 Hidden API 限制
  ├─ startAntiDumperDaemon()    → 反调试守护（TracerPid + Frida）
  ├─ readAsset("payload.dat")   → 读取加密载荷
  ├─ buildDecryptionKey()       → 三段密钥拼装
  ├─ decrypt(payload, key)      → 自定义流密码解密
  └─ parseDexPayload()          → InMemoryDexClassLoader 加载真实 DEX

解密算法

key = SHA256("Sh3ll_L0ad3r_K3y_2024!")
iv = payload[:16]
keyStream = SHA256(iv + key)
for i in range(len(ciphertext)):
    b = (ciphertext[i] - key[i % 32]) & 0xFF
    b ^= key[(i + 7) % 32]
    b ^= keyStream[i % len(keyStream)]
    result[i] = b

Q3：群组数量（部分分析）

分析过程

在 E01 中定位到通联工具 com.socialchat.social_chat_app：

  • FlutterSharedPreferences.xml 中 username = fangjunlang
  • 数据库 social_chat.db（188KB）使用 SQLCipher 加密
  • 数据库密钥：flutter.db_password = Pgs-dbw1776826167125Good

已知密钥参数：

来源 内容
password.json {"key":"+eogI/0tK0JRzDXjP1Bs1hb+xi/OM/2pqqW+NNIc4J0="}
SharedPreferences flutter.db_password = Pgs-dbw1776826167125Good

解密方案：

  • 方案 A：PRAGMA key = "Pgs-dbw1776826167125Good" + 标准 SQLCipher 参数
  • 方案 B：用 flutter.db_password 解密 password.json 中的 AES 密钥后作为 raw key

⚠️ 需要匹配 App 绑定的自定义 ARM64 libsqlcipher.so 编译参数才能解密。

Q4：IoT 漏洞获取用户数量（部分分析）

分析过程

通过解密 Q1 的 payload.dat，在 classes3.dex 中发现真实的 IoT 工具代码：

应用结构：

com.example.predictor
├── ChatDatabaseHelper    ← SQLCipher 加密数据库管理
│   ├── KeyDeriver        ← PBKDF2 密钥派生 (10000 iter)
│   ├── getRecordCount()  ← 返回用户数量
│   └── getAllRecords()   ← 返回全部用户清单
├── ChatRecord            ← 用户数据模型
│   ├── name, age, score, province, level, recommendation, timestamp
├── MainActivity          ← "优质客户AI判定" 入口
└── HistoryActivity       ← "历史判定记录" 用户列表

密钥派生逻辑 (KeyDeriver)：

password = getAppSignatureHash() + "Pr3d1ct0r" + "v2.0_release_S@lt" + "X9kZ!qW3"
salt = "Pr3d1ct0r"
key = PBKDF2WithHmacSHA256(password, salt, 10000, 256)  // hex encoded
// fallback: "f4ll8ack_k3y_2024_pr3d1ct0r"

数据库： chat_history.db（12KB），加密配置 PBKDF2_v1 / iter=10000。

⚠️ 同上，需匹配自定义 SQLCipher 编译参数解密。
